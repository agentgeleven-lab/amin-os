# Amin os

**把地图、角色状态、回复灵感与资料管理，放进酒馆里的一个悬浮工作台。**

Amin os 是用于 **SillyTavern / TauriTavern** 的前端扩展。点击悬浮入口打开侧栏，在可自定义的磁贴首页进入各个应用。适合希望一边聊天、一边查看世界资料、整理状态和控制持续效果的用户。

当前版本：**0.17.0** · 无需编译 · 支持桌面与窄屏布局

## 功能一览

| 应用 | 可以做什么 |
| --- | --- |
| **世界书管理** | 为角色设置专属全局世界书组合及条目启用规则，离开角色自动撤回插件接管的改动。 |
| **地图** | 查看与编辑地点、路线、多层地图；使用 AI 生成地图草稿，检查后保存。 |
| **世界状态** | 在 OS 窗口或消息楼层管理变量、规则、模板与历史；“联动更新”统一各应用的读取权限、世界书提示和整批更新。旧楼层显示只读快照。 |
| **人物卡** | 登记 PC / NPC、外观与发型，查看实时穿戴及只读关联资产、关系、记忆、场景和日程；属性绑定世界状态，支持本地 D20 / CoC 7 检定及人物资料跳转。 |
| **背包与账本** | 管理物品、穿戴部位与层次、湿污破损、资源和货币；消耗、收支和转交先预览并留下账目。 |
| **人物关系** | 管理有方向的关系与关系图，按选定剧情生成更新建议，配置数值阈值提醒；反向关系独立保存。 |
| **骰子** | 本地通用公式、D&D D20 与 CoC 7 检定；保存固定结果，追加到行动草稿后随同一条消息发送，不调用酒馆官方 `/roll`。 |
| **场景与时间** | 管理剧情时钟、场景、旅行、NPC 日程及离场规则；支持自定义历法与活动耗时，预览后确认变化。 |
| **剧情档案** | 管理任务、线索、事实、人物记忆、伏笔与编年史；支持自动草稿和前作选择引用，保留来源，确认后按条启用。 |
| **跨应用存档** | 保存完整剧情状态与楼层检查点，预览恢复或从有效检查点新建分支；支持恢复前备份及 JSON 导入导出。 |
| **回复选项** | 生成候选／设置两页；支持角色扮演、作者构想和草稿扩写，文风与内容风格集中设置。只填入、不自动发送；发送后清空临时候选。 |
| **能力面板** | 从世界书导入或手动添加能力；支持属性检定、限时、叠加、周期结算及明确消耗的行动结算。能力库跨聊天共享，生效记录按聊天隔离。 |
| **信息面板** | 检索人物、事物或世界资料，分组收纳；编辑后可把修改前后记录用于后续剧情。 |
| **势力概览** | 管理组织、阵营、地区及用户专属评估，检查 AI 变更后确认。 |
| **语音朗读** | 选择云端或本地引擎，分别调整对话与旁白；分段生成、重听、下载，并浏览本机历史音频。 |
| **AI 设置** | 逐应用选择 Amin 独立 API、酒馆当前完整预设或指定酒馆连接配置；管理异步预设与生成任务。 |
| **设置** | 调整 OS 主题、单应用外观、磁贴、背景动效和消息楼层窗口；检查剧情索引与空间信息，按需测量 Amin 恢复和读写。 |

### 联动工作台新增入口

- **能力面板 → 行动结算**：选择资源／物品消耗、人物绑定数值增减、已有固定骰点及耗时，先预览再确认；结果可复制到聊天草稿，失败只重试保存，不重复扣除。
- **人物卡 → 人物关联总览**：汇总资产、关系、记忆、场景和日程，只读引用原应用数据。能力目标仍是文本，不自动按同名人物归类。
- **剧情档案 → 任务／线索**：记录进度、来源、可信程度及关联；可由 AI 建议生成。保存记录不自动完成任务或发放奖励。
- **世界状态 → 联动更新**：查看本次运行最近的变量变化与错误；展开“AI 资料预算与固定保留”设置字符预算，并查看模块纳入原因。预算默认关闭，必需资料超限会提示，不静默丢弃。
- **设置 → 剧情文件存储**：只读检查当前聊天楼层／Swipe、分支来源及可达文件大小；同页性能诊断可手动记录 Amin 恢复、保存和文件读写。记录仅在本次页面内存中，不代表 TT 全局耗时或同步流量。

全局垃圾回收、自动任务奖励和完整跑团规则尚未提供。交付范围与后续安排见[规划与验收](docs/NEXT-STEPS.md)。

### 0.17 剧情外置存储

聊天保存索引入口，消息与 Swipe 保存稳定标识；历史变量存入扩展文件存储，以差量和内容复用减少重复数据。分支建立独立索引，继承分支点之前的记录并共用历史文件。正文编辑保留原状态，不自动推断变量变化。详见[聊天索引与 Swipe](docs/story-chat-index.md)。

跨设备需要同步聊天文件和对应扩展存储。缺失文件、未知消息或重复标识会阻止恢复；插件不会按相同楼层数字猜测。删除聊天不会自动清除全部外置文件，避免破坏其他分支仍在使用的记录。

### AI 生成与联合初始化

人物卡、人物关系、背包与账本、场景与时间、剧情档案均可展开 **AI 生成／补充**。选择角色卡、用户设定、世界书或聊天范围，生成可编辑的建议，再选择、预览并确认保存。世界状态 → 联动更新中的 **联合初始化** 可同时建立多应用资料。

提供仅新增、补充缺项及按剧情更新三种方式，沿用各应用 AI 渠道；多应用任务使用“联合初始化”渠道。手动生成无需开启后台联动，不改变原联动权限。详见 [AI 生成资料指南](docs/GENERATION-0.15.md)。

### 统一关联与剧情更新

入口为 **世界状态 → 联动更新**。人物、世界状态、背包、关系、场景、剧情档案、能力效果、地图、势力和信息面板共用一份更新协议；骰点只读。每个模块独立设置参与联动、提供资料和允许模型更新，日常回复使用小白 X 变量 2.0 的 `<state>`，由小白自动执行；Amin 刷新应用窗口。磁贴是否显示不决定权限。

统一世界书条目仅提供变量更新协议与规则；当前人物、背包、场景等资料及关联目录由插件插入发给 AI 的消息上下文，不改写可见聊天正文。联动页可分别预览世界书规则与消息内资料；自定义规则和位置设置保留。关联目录展示稳定 ID 和缺失引用，也可以手动关联任意已有条目。迁移、变量根和回退说明见 [0.16 变量 2.0 指南](docs/STATE2-0.16.md)。

记忆与前作引用融入剧情档案，NPC 日程与自定义历法融入场景，穿戴外观连接人物卡和背包，关系增加 AI 建议及阈值提醒，能力效果增加叠加与周期结算。存档增加完整楼层检查点与酒馆分支衔接。所有内容继续作为 Amin OS 内部应用发布。

### 跑团基础

**跑团数据现在按明确职责衔接。** 世界状态保留人物数值的唯一来源；人物卡保存 PC / NPC 资料和字段绑定；背包与账本管理物品、资源及每次变更；人物关系保存独立的有向关系。删除人物不会连带删除世界状态、资产或关系引用，相关应用会显示缺失人物并允许后续修复。完整步骤见 [0.13 跑团工作流](docs/RP-0.13.md)。

**人物检定、能力发动和固定骰点分开确认。** 人物卡可直接使用绑定值做 D20 或 CoC 7 检定；能力面板也可在发动前选择人物属性、预览当前世界状态数值并在插件内掷骰。结果一经掷出即固定，点击“追加固定结果到草稿”只写入酒馆输入框，不自动发送；确认效果是另一个明确操作，也不会自动扣除生命或资源。

**持续效果可以跟随游戏时钟计时。** 发动能力时可填写分钟、小时或天数，之后查看剩余时间、暂停、恢复、重设或取消时限。到期记录仍保留并显示“已到期”，但不再加入剧情提醒；插件不会自动删除效果或生成结算剧情。推进时间前会预览本次新到期的效果。

**场景与时间新增相邻路线旅行。** 旅行只列出当前位置一跳可达、已发现且可通行的路线。已知距离和速度会换算为整数分钟，也可明确覆盖；无法计算时必须手填耗时。预览会同时列出目的地、游戏时间、抵达场景和新到期效果，确认一次后把地图位置、场景与时钟作为同一项变更保存。

**跨应用存档保存当前剧情状态。** 每个聊天最多 20 个命名存档；恢复前自动建立一份安全备份，保留最近 5 份。存档包含人物、背包、关系、场景、效果、剧情档案、固定骰点、地图、世界状态、势力与信息资料，不包含聊天消息、全局界面设置、跨聊天能力库、API 配置或密钥。恢复把状态追加到当前聊天尾楼，不会回退或删除酒馆消息；消息与回复候选仍使用酒馆自己的分支或检查点功能。

**所有剧情变更先预览，再确认一次。** 如果保存失败，已确认结果保留在当前聊天内存中，页面只提供“重试保存”；重试不会重复扣除、转交、旅行、掷骰或发动。切换聊天、回复候选或依赖数据变化后，旧预览会失效并要求重新核对。

页面沿用 Amin OS 主题、共享表单、卡片和窄屏单列规则。自动测试与隔离浏览器预览不代表真实 SillyTavern / TauriTavern、模型供应方、物理手机触控与软键盘已完成验收。

### 界面与基础应用

**骰子作为单独应用使用。** 在通用骰、D&D 或 CoC 7 页填写检定，点击“掷骰并记录”，检查明细后将一条或多条结果追加到聊天草稿，再由酒馆发送按钮把行动正文与骰点一起发出。随机数在插件内产生，结果一经记录即固定；重新请求模型、续写或切换 AI 回复不会重新掷骰。“用相同设置重掷”会新增一条记录。回复选项扩写会保留当前聊天中完整匹配的已登记骰点块。详见[骰子说明](apps/dice/README.md)。

**场景与时间合并为一个应用。** 在“时钟”设置日期、推进分钟或小时，在“场景”记录名称、人物、环境和物件；先预览再确认，保存失败重试不会再次推进。切换场景保留当前故事时间，地图引用只读取地点。时钟不会按模型轮次自动前进，休息按钮只推进时间。详见[场景与时间说明](apps/scene/README.md)。

**伏笔与编年史合并为剧情档案。** 伏笔可标记待回收、已回收或已放弃；编年史可由所选真实楼层起草，AI 结果先进入可编辑预览，采用后仍需明确保存。场景的模型引用默认关闭，剧情档案每条引用也默认关闭；启用后仅使用符合当前分支与来源校验的已保存资料。导入档案须重新绑定当前聊天来源。详见[剧情档案说明](apps/journal/README.md)。

**世界状态同时保留 OS 窗口与消息楼层入口。** 点击 OS 磁贴会在插件窗口中打开完整工作台；点击最新非系统消息下的“世界状态”会在楼层窗口打开。两个入口共用当前聊天的状态、配置及历史；切换入口时，当前编辑工作台显示在新选择的位置。旧楼层只读展示当时快照，浏览不会恢复变量。空聊天也可在 OS 内编辑，发送消息后不会自动跳到楼层。详见[世界状态集成说明](apps/status/README.md)。

**首页磁贴采用细网格定位。** “编辑布局”可选择 4 格宽或 6 格宽，并调整整体大小（70%–100%）；4 格宽时每个格子更大。 拖到的小格作为左上角，完整占位预览显示可放或冲突；已占用区域不会挤动其他磁贴，空白位置会保留。尺寸提供 1×1、2×1、1×2、2×2、3×2、4×2、2×3、2×4；每块可独立设置背景、文字、图标颜色，也可恢复默认配色。

**楼层按钮可自定义排列。** 点击消息下方的“调整排列”后拖动排序；手机也可长按按钮进入调整模式，松手后拖动。调整自动保存并同步到所有楼层。设置 → 楼层窗口提供上下移动、放入“更多”、按钮整排对齐及恢复默认排列；按钮栏和打开的窗口可分别对齐。

**所有应用沿用原有主题，统一界面规格。** 标题、分页、卡片、表单、主要操作与反馈使用同一套样式；窄窗口与手机布局转为单列，增大触控区域，长页签可横向滚动。AI 设置重开窗口保留未保存内容，外观设置跨页保留草稿，语音分为“朗读与分段”“声音设置”“音频库”。楼层应用共用消息列表刷新调度，减少重复扫描。

**楼层语音按稳定消息标识与正文版本关联。** 删除前面的楼层、调整顺序或切换回复后，不会仅因数字楼层相同而拿到另一条消息的音频。旧版录音保留在本机音频库：打开 OS 的“语音朗读 → 音频库”，勾选“全部本机历史”查看来源与保存日期，并重听或下载。旧数字楼层来源不会自动绑定到当前消息；楼层窗口仍只显示自己的音频。跨来源旧录音不提供重新生成按钮。

骰子是检定辅助工具，不包含完整 D&D／CoC 规则。手动恢复跨应用存档把剧情状态应用到当前尾楼；消息回滚或创建分支仍由酒馆完成，Amin 根据对应索引恢复剧情状态。自动测试和本地模拟预览不代表真实酒馆版本、API 供应方或实际手机已完成验证。

### 回复选项怎么用

详见[回复选项使用说明](apps/reply/WRITING.md)。主页面用于生成、比较和选用候选；文风、内容风格及其提示词、创作模式和其他生成要求集中在“设置”页。

1. 打开「回复选项 → 设置」，选择模式、文风和内容风格；需要时编辑并保存提示词。
2. 返回「生成候选」生成一批建议，或先在聊天输入框写草稿，再点“根据草稿扩写”。
3. 选择候选填入输入框，核对并自行发送。发送前可改选或撤销；发送后清空候选。

候选仅存在窗口内存中，不保存到剧情存档。已移除独立改写草稿、单项重抽和保留满意项；旧文风转换入口跳转到回复选项设置。楼层窗口只参考截至该楼的聊天，各窗口任务独立。文风和内容风格通过提示词约束，实际效果仍取决于模型。

世界状态的“读取用户设定描述（Persona）”位于生成设置，默认关闭；缺少描述时会提示。此开关不自动开启角色卡或世界书读取。

### 你可以怎样布置它

- 自定义磁贴名称、打开的应用和尺寸；支持新增、复制、删除、拖动排序，同一应用可以有多个入口。
- 提供小、中、宽、竖向长磁贴，以及 Windows Phone / Windows 10 风格；Windows 10 窗口可选浅色或深色。
- 调整圆角、字号、间距、透明度和窗口尺寸；拖动窗口边缘的短横把手可以调整高度。
- 设置背景图片、磁贴图片、樱花或视频动效。动效限制在磁贴区，仍能正常点击按钮。
- 在消息楼层显示地图、世界状态、骰子、场景与时间、剧情档案、回复选项、势力概览、能力面板、信息面板、世界书管理和语音按钮，统一对齐与窗口样式，也可分别关闭；窗口按打开顺序排列。

### 手机地图操作

在地图画布内双指张开放大、合拢缩小，双指移动可平移；缩放以双指中心为基准。双指手势开始时取消未提交的地点拖动或格子刷选，手指全部离开后更新视图。单指和鼠标原有操作保留；适用于连线、方格及六边形地图。

### 地图地点太少时

地图 → AI 的“地点覆盖程度”默认全面，可选适中或简略。全面模式按当前层级覆盖各分区、资料明确地点及必要交通枢纽，不再默认限制为 3–8 个地点或 12 个总节点。新地图与新增模式均参考最近 30 条非系统聊天；共享预设需启用对应资料块。

新增“主要地点／自由”层级：不受固定空间尺度及上级地图边界约束，按剧情重要性收录地点，可混合城市、建筑、房间等尺度；用户明确范围仍优先。

原六类生成层级各有尺度边界、覆盖清单、连接规则和排除内容，并要求模型检查遗漏。可展开“查看当前层级的生成约束”阅读；这些是提示词引导，并非逐地点的自动语义校验。

请核对生成层级及世界书读取范围，较大的地图可提高 AI 设置中的输出预算，或分地区生成。已有地图可用“根据资料与聊天记录新增地点和道路”继续补全。生成只进入草稿，保存后生效；全面模式不代表联网检索或穷尽所有现实地点。

### 共享能力库

能力面板中的能力原文、提醒规则、按钮外观及布局保存在当前酒馆用户的全局设置里，跨角色和聊天复用。导入后无需保留原世界书绑定，也不会跟随来源自动更新。目标、具体指令和发动记录仍按聊天隔离；修改能力只影响之后的新发动，原有生效记录保持当时规则。

更新后，分别打开有旧能力的聊天并进入能力面板，即可自动收纳。相同能力副本不重复导入；有差异的版本分别保留，旧聊天数据也保留。共享范围为同一酒馆用户，不自动跨设备或跨账号同步。

在“能力管理”中可以删除能力，移除共享库里的按钮；已发动效果保留，在“生效中”单独暂停或解除。误删可展开“已删除能力”恢复，原世界书不受影响。

### 回复选项的两种模式

在回复选项的“设置”页选择“创作模式”，OS 内和消息楼层窗口都可使用。

- **角色扮演**：沿用原来的对白、动作和人称设置，拟写用户角色的回复。
- **创意写作**：以作者 / 编剧视角规划下一幕事件、角色动机、冲突、转折与伏笔，不直接扮演角色或续写正文。在设置中填写独立的“剧情方向”和“作者要求”；也可先在聊天输入框写构想，再点击“展开作者构想”。

回复选项提供独立的“内容风格”选择：正常、NSFW、暴力、无厘头，可与角色扮演或创意写作搭配。每种风格单独保存可编辑提示词，只附加选中项。正常默认不追加，NSFW 默认留空并保留原设置；暴力和无厘头提供可修改的基础风格要求。旧 NSFW 开关自动迁移为对应选择。仅作用于回复选项，不改变其他应用。

选项方向与剧情方向改为可添加、删除、编辑和启用／禁用的条目，仅抽取启用且非空的方向。原有逐行方向会自动迁移，全部禁用时不请求模型。设置中可编辑“角色扮演模式提示词（角色定位）”、“剧情模式提示词（作者 / 编剧定位）”、作者补充要求和 NSFW 提示词；输出 JSON 格式仍由插件约束。

两种模式分别保存生成要求，切换时清除旧候选。选择方案只填入输入框，仍由你决定是否发送，可撤销填入。默认保留原有角色扮演模式。

## 第一次使用

1. **选择生成方式：** 在「AI 设置 → 应用渠道」为需要 AI 的应用选择 Amin 独立接口、酒馆当前配置或已保存的酒馆连接配置，然后点击该应用的「保存应用渠道」。
2. **使用独立接口时：** 在「API 连接」读取酒馆连接后直连，或手动填写地址、密钥和模型；可拉取模型列表，填写配置名称并「保存为新配置」，再在应用渠道中选择它。
3. **建立跑团基础：** 先在世界状态建立数字字段，再在人物卡绑定属性；随后登记背包、资源与人物关系。详细顺序见 [0.13 跑团工作流](docs/RP-0.13.md)。
4. **确认场景与行动：** 设置游戏时钟和当前位置；骰点在插件内产生固定结果，追加到草稿后仍由你使用酒馆按钮发送。旅行、数值、资产、关系与效果变更都先预览再确认。
5. **留下剧情状态存档：** 重要节点在「跨应用存档」创建命名存档并导出 JSON。恢复只应用到当前聊天末尾；聊天正文和回复候选使用酒馆自己的分支或检查点。
6. **调整外观：** 在「设置」选主题，在首页「编辑布局」布置磁贴。旧布局升级时会补入 0.13 新应用一次；之后手动移除的磁贴不会反复自动加入。

### 模型请求如何工作

在「应用渠道」中，每个应用独立选择生成方式；原有配置默认继续使用 Amin 路由。

| 生成方式 | 使用的连接与预设 |
| --- | --- |
| **Amin 独立接口** | 浏览器直接请求接口，使用 Amin 保存的 API 参数与共享异步消息预设。可读取酒馆连接信息后直连，也可手动配置。 |
| **酒馆当前配置 · 完整预设** | 调用酒馆静默生成（Quiet），由酒馆按 Quiet 触发规则组装当前上下文和完整提示词预设。主聊天使用的连接保持不变。 |
| **指定酒馆连接配置 · 采样参数** | 通过酒馆的连接配置请求服务使用所选接口、模型及生成参数；消息内容由 Amin 组装，不等同于调用该配置的完整 Prompt Manager 提示词栈。 |

酒馆原生选项需当前宿主提供对应接口；不可用时会显示原因。选择指定配置后点击该应用的「保存应用渠道」；配置列表可刷新，刷新会保留未保存的选择。候选生成与根据草稿扩写使用回复选项渠道；遗留文风转换渠道不再用于当前回复选项流程。语音使用自己的专用接口。

Amin 直连支持读取 OpenAI、自定义 Chat Completions 兼容接口与 OpenRouter 的连接信息。酒馆禁止读取密钥时可改为手动配置；直连接口需要允许浏览器跨域，`/models` 不可用时可手动填写模型。独立 API 密钥默认仅在页面会话中保留，勾选「记住密钥」后才在当前浏览器保存。

「异步预设」编辑 Amin 提交的有序消息块；「任务记录」显示任务、渠道和请求预览。Quiet 的最终完整请求由酒馆组装，Amin 只展示提交给它的工具任务，不能在此完整预览。取消 Quiet 会停止 Amin 等待并拒绝采用迟到结果，宿主已经开始的静默生成可能仍会完成。详见[应用渠道说明](ai/CHANNELS.md)。

## 信息面板怎么用

### 查资料与收纳

在「生成资料」填写人物、物品、地点、组织或世界名称，选择酒馆资料、互联网或两者。酒馆来源可包括角色卡、角色绑定世界书、额外选中的世界书和聊天记录。

AI 会整理命中的资料片段，标注来源、推测、未知或新增设定。希望补充原资料没有的信息时，勾选允许创作并填写要求。检索预算有限，结果不保证完整，来源引用也需要自行判断。

成功生成后，资料自动保存到**当前聊天**。切换角色再返回、刷新后仍可从「资料收纳」打开；同名同类型对象归在一起，字段分类折叠显示。不同聊天各自保存。编辑中的资料可点「保存资料（不影响正文）」。

### 编辑与影响剧情

**仅查询、生成或收纳资料，不会自动影响正文。** 编辑字段后，先预览，再点击「确认应用到当前剧情」：

- 每次确认保存完整的修改前、修改后资料。
- 后续正文请求按顺序附带累计修改记录；同一字段以最后一次修改为当前状态。
- 例如「守卫 → 医生」后又改为「医生 → 城主」，两次记录都会发送，当前职业为城主。
- 「一键重置当前面板修改」恢复本轮修改前资料，停止发送该面板的累计记录；历史版本保留，其他面板不受影响。

这通过剧情提醒影响**后续生成**，不会改写已发送聊天，也不会直接改动原世界书、地图或状态栏。未知和推测字段不会作为确定事实发送。累计资料超过提醒上限时会提示，可在「检索设置」调整。

### 联网搜索

联网搜索需要单独的 **Tavily Search 或同格式兼容接口**与搜索密钥，在信息面板「检索设置」填写。模型密钥不能替代搜索密钥。搜索密钥只保留到本次页面刷新；搜索词发送给搜索服务，选取的资料交给共享模型整理。

## 能力面板怎么用

添加能力时，可以选取世界书中的条目，也可以自己填写能力原文。给能力设置按钮名称、图标、大小、颜色、分组及默认操作，按自己的习惯排布。

持续提醒规则可以手写，也可让 AI 根据能力原文起草；采用草稿并保存后，再按目标和作用范围发动效果。能力生效时保存规则快照，世界书后续变化不会自动改掉已经发动的规则。能力面板和信息面板分别管理数据。

## 常见问题

| 遇到的情况 | 可以先检查什么 |
| --- | --- |
| 安装后没看到入口 | 确认已启用、刷新并打开聊天；检查是否提示旧独立插件仍在运行。 |
| API 报错或拉不到模型 | 检查地址、密钥、模型及跨域支持；不支持模型列表的接口可手填模型名。 |

| 换设备后布局或密钥没同步 | 磁贴布局和共享 AI 配置主要保存在当前浏览器；它们不是跨设备同步配置。 |

| 恢复跨应用存档后聊天消息没有回退 | 这是预期行为。存档只把插件剧情状态应用到当前尾楼；请用酒馆原生分支或检查点恢复消息和回复候选。 |
| 骰点没有自动发到聊天 | 先点“追加固定结果到草稿”，检查行动正文与骰点块，再使用酒馆原来的发送按钮。插件不会调用官方 `/roll` 或自动发送。 |

## 世界书管理怎么用

也可从消息楼层的「世界书管理」按钮打开。开关位于 OS 设置 → 楼层窗口，支持统一或单独尺寸；窗口按打开顺序排列。楼层入口操作的是当前角色组合，与 OS 内共享数据，不是该楼层的历史快照。

1. 已自定义主页的用户，在「编辑布局」新增磁贴，把打开的应用设为「世界书管理」。现有磁贴布局不会被重置。
2. 在「展示范围」选择希望在插件里看到的世界书。展示筛选不会改变世界书启用状态。
世界书列表统一收进「选择启用的世界书」下拉菜单，默认收起，展开后多选；勾选自动保存并应用当前角色组合，暂停时只保存。取消勾选只撤回插件接管部分。通过独立的「当前角色已启用的世界书」下拉栏选择，直接在下方编辑条目，接管条目仍按书折叠收纳。

3. 打开单人角色卡，在「角色组合」勾选需要临时挂为全局的世界书。在第二个下拉栏选中世界书后，可逐条选择保持原样、启用或关闭，也可搜索和批量设置。每本书提供「全部启用」「全部关闭」「全部恢复原样」：作用于整本书，不受搜索或勾选影响，保存组合或临时应用后生效；恢复原样撤销条目覆盖，不撤下世界书。
4. 点击「保存角色组合并应用」。同一角色的不同聊天共用组合；也可「仅本次临时应用」，不覆盖角色保存的组合。
5. 切换到其他角色、群聊或离开角色后，插件恢复接管的条目开关，并撤下自己临时启用的书。原本就全局开启的书、其他无关全局书不会被撤下。

条目设置只修改共享世界书的 `disable` 开关，不改正文、关键词、常驻/触发类型。启用条目不等于强制注入，仍遵循酒馆的原触发条件。因为开关属于共享世界书，它在当前角色期间也会影响该书其他引用方式。

- 「接管记录」可查看原状态和应用状态，并选择保留某本书为全局、保留条目当前状态，或者撤回全部插件改动并暂停。
- 手动关闭世界书后，同角色切换聊天不会强行重新开启；需要时点击「重新应用已保存组合」。
- 恢复时若条目开关已不同于插件写入值，则保留外部修改，并在操作提示中记录。外部修改最终恰好与插件写入值一致时无法仅凭状态区别，可先点「保留此状态」释放接管。
- 「暂停自动应用」阻止新的自动应用；离开角色仍清理旧角色接管项。「撤回全部」同时暂停，避免马上重新套用。
- 恢复日志同步保存在当前浏览器本地及扩展设置。保存失败时保留待恢复记录，不继续套用下个角色。卸载或停用插件前先撤回全部；直接关掉整个酒馆时无法保证网络写入，重开后会依据当前角色处理恢复。
- 第一版面向单个酒馆页面操作；不要同时在多个标签或设备编辑同一世界书。书被改名或条目被删除时会提示，不会自动猜测或改写另一份书。

开发验证：`npm test`、`npm run check`；`test/worldbooks-preview.html` 提供不连接真实酒馆的角色切换演示。模拟测试不代表所有酒馆分支的实际运行验证。

世界书条目写入后会从服务端回读验证开关，再更新缓存；若酒馆编辑器正打开同一本书，会在本次操作结束后重新载入，避免沿用旧开关显示。原始导入数据中的 enabled 字段按酒馆原生开关同步。

### 语音朗读（0.8.28）

新增本地东雪莲语音应用和楼层朗读窗口。已有自定义主页可在“编辑布局”添加指向“语音朗读”的磁贴；楼层入口在设置中开关。使用前启动本机 Azuma Bert-VITS2 2.3 服务，默认地址 `http://127.0.0.1:9883`。支持编辑朗读文本、分段、暂停、继续、停止、语速和音量。切换聊天或编辑消息会停止当前朗读。详见 [语音接入说明](apps/tts/README.md)。
