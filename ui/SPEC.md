# Amin OS 统一 UI 规范

版本：UI v2 · 2026-09-23

适用范围：本轮重做后的主窗口、全部应用、楼层窗口与世界状态 iframe。
本规范记录代码中的实现约定。模拟宿主浏览器验证见第 8 节；实际酒馆与真机仍待验证。

## 1. 设计原则

沿用现有主题颜色与用户外观覆盖，统一布局、控件尺寸、间距和反馈。窗口标题、当前数据范围、操作、正文之间建立清楚的层次；地图、状态字段、回复候选和骰子结果保留适合业务的展示方式。

普通应用采用「当前上下文 → 可选分类导航 → 操作区 → 内容卡片 → 可选保存区」。窗口头部显示应用名，页内上下文保持紧凑。数据作用范围需要直接说明，例如“当前聊天”“当前剧情状态”“本楼历史快照”“跨聊天预设”。

## 2. 主题变量

外观配置由 `settings/appearance.js` 统一解析；应用独立设置优先于全局设置。现有主题为：Windows 10 浅色、Windows 10 深色、薄荷夜色、深海蓝、旅人纸页、樱花物语、夜色紫晶、极简墨白。

| Token | 使用位置 |
| --- | --- |
| `--amin-bg` | 窗口和页面底色 |
| `--amin-card` | 内容卡片与提示背景 |
| `--amin-control` | 输入框、次要按钮与原文预览 |
| `--amin-text` / `--amin-muted` | 正文 / 次要说明 |
| `--amin-line` | 边框、分隔线 |
| `--amin-accent` | 主按钮、选中边框、结果强调 |
| `--amin-ink` | 主按钮在强调色背景上的文字 |
| `--amin-accent-text` | 强调文字；Windows 主题按可读性使用正文色 |
| `--amin-font` / `--amin-radius` | 基础字号 / 圆角 |
| `--amin-gap` / `--amin-space` | 用户密度间距 / 组件实际间距 |
| `--amin-opacity` / `--amin-blur` | 窗口透明度 / 背景模糊 |
| `--amin-floor-width` / `--amin-floor-height` | 楼层窗口桌面宽度 / 当前设备使用的高度 |
| `--amin-floor-desktop` / `--amin-floor-mobile` | 两类设备的楼层窗口高度配置 |

正文统一使用 Segoe UI、Microsoft YaHei、sans-serif；品牌保留本地 Courgette 字体。业务应用不另建固定深色配色。Windows 桌面风格、自定义背景和磁贴效果继续由各自配置控制。

## 3. 尺寸与响应式

| 项目 | 当前代码约定 |
| --- | --- |
| 默认字号 | 13px；用户可设 11–20px |
| 正文 / 控件行高 | 通常 1.6 / 1.5 |
| 默认圆角 | 14px；用户可设 0–24px；Windows 外形保留直角 |
| 页面与卡片间距 | 舒适 14px、紧凑 8px；组件间距至少 8px |
| 普通操作行 / 标签页间距 | 8px / 4px |
| 桌面控件最小高度 | 普通控件 38px；标签页和楼层入口通常 36px |
| 手机或粗指针控件 | 按钮、输入框、选择框、复选标签至少 44px 高 |
| 复选框图形 | 18 × 18px；通过整行标签扩大点击区域 |
| 手机输入字号 | 至少 16px，避免输入时浏览器自动放大 |
| 多行输入 | 通常至少 100px 高，允许纵向调整 |
| 表单列数 | 常规双列；应用容器 ≤540px 或视口 ≤640px 时单列 |
| 主窗口默认尺寸 | 448 × 720px；桌面按可用视口约束 |
| 手机主窗口 | 视口 ≤640px 时使用可见视口宽高减 16px，四边留 8px |
| 楼层窗口默认 | 桌面宽 900px、高 65dvh；手机高 55dvh；均受容器约束 |
| 手机楼层宽度 | 容器 ≤540px 或视口 ≤640px 时使用消息可用全宽 |

表单列使用 `minmax(0,1fr)`；文本允许换行，长链接和结果允许在词内折行。320、390、430px 是必测宽度。桌面磁贴、能力磁贴和地图属于专用网格；手机单列要求主要针对表单和正文卡片，不强制将所有快捷按钮排成一列。

## 4. 组件契约

所有应用挂载在 `.amin-ui` 内，或将该类加在应用根节点。普通页面使用 `.amin-app-page`。已有骰子页使用等效的 `.amin-page.amin-dice` 流式布局。

| 类名 | 语义与行为 |
| --- | --- |
| `amin-context` | 当前对象、作用范围或一句操作说明，底部分隔 |
| `amin-tabs` | 紧凑横向分类，空间不足时换行 |
| `amin-toolbar` / `amin-inline` | 可换行的操作行 / 内联信息 |
| `amin-stack` | 统一间距的纵向内容 |
| `amin-card` | 中性内容卡片 |
| `amin-section-heading` | 小节标题，可配元数据或局部操作 |
| `amin-form-grid` / `amin-field` | 响应式表单 / 标签与满宽控件 |
| `amin-check` / `amin-span-full` | 复选行 / 跨列表单项 |
| `amin-primary` | 当前区域的主要操作，通常一个 |
| `amin-meta` / `amin-help` | 次要信息 / 补充说明 |
| `amin-result` | 结果卡片，用侧边强调线突出 |
| `amin-empty` | 空状态说明，可附下一步操作 |
| `amin-notice` | 状态提示，空内容时隐藏 |
| `amin-savebar` | 集中的保存或提交操作 |
| `amin-scroll` | 专用 flex 布局中的明确滚动区 |

`.amin-app-card` 专指桌面启动磁贴，内容卡片使用 `.amin-card`。除 `.amin-app-page` 外，共享组件不添加 `app-` 前缀。

表单标签必须可见，说明放在字段附近；复选框与文字组成同一可点击标签。进度、错误、完成可以使用 `data-state="busy|error|success"`，同时显示具体文字。错误说明应指出发生了什么以及下一步可做什么。禁用状态不能遮蔽解释文字。

| 应用 | 当前页面组织 |
| --- | --- |
| 桌面 | 品牌与窗口操作、应用磁贴、磁贴编辑；保留尺寸、顺序、主题和背景效果 |

| 世界状态 | 当前楼层工作台承载状态编辑、生成、规则、模板和记录；历史楼层显示只读快照 |
| 能力面板 | 能力面板 / 能力管理 / 生效中 / 变更记录 / 提示预览；能力磁贴、发动字段和效果卡片 |
| 信息面板 | 资料面板 / 生成资料 / 历史版本 / 检索设置；资料分组、字段编辑、变更预览 |
| 势力概览 | 总览 / 组织 / 联盟与阵营 / 地区 / 评估排行 / 生成与规则；资料卡、编辑表单与变更比较 |
| 世界书管理 | 角色组合 / 展示范围 / 接管记录；折叠分组、条目选择和局部操作 |
| 回复选项 | 写作工作页导航、生成操作、候选卡片和折叠设置；结果填入聊天草稿 |
| 文风转换 | 模式与预设、原文、可编辑结果、填回操作；可嵌入写作工作页 |
| 语音朗读 | 配置与文本、对话 / 旁白设置、分段卡片、生成与音频结果操作 |
| AI 设置 | API 连接 / 应用渠道 / 异步预设 / 任务记录；分类卡片与明确保存反馈 |
| 外观设置 | 整体外观 / 单个应用 / 楼层窗口 / 背景与动效；修改集中保存 |

新增应用先选择已有页面与组件，再添加确有必要的业务布局。应用自己的样式应只描述地图、骰子数字、音频分段等业务特点。

## 6. 主窗口、楼层和 iframe

**主窗口**：普通应用由 `.amin-app-pane` 承担主滚动，内容页自然增长。手机根据 `visualViewport` 调整窗口位置和大小；打开时隐藏浮动启动器，保留头部关闭按钮。地图的专用内容区继续自行滚动。

**楼层窗口**：入口按钮和头部允许换行，窗口宽度受消息容器约束。手机忽略保存的桌面像素宽度，使用可用全宽；桌面保留独立宽度、对齐、统一高度或自动高度配置。普通应用由 `.amin-reply-floor-body` 承担主滚动。长原文、JSON 和受限选择列表可独立滚动，普通表单不要再套第二层主滚动区。

**世界状态**：最新有效楼层打开当前状态工作台；较早楼层展示只读快照，并提供前往当前工作台的入口。历史翻页不恢复变量。没有聊天消息时，保留主窗口内的编辑入口。当前状态、生成和历史记录必须在文案上说明其作用范围。

**状态 iframe**：自行加载共享控件、主题同步和 `workbench-frame.css`；父页面不能直接为 iframe 内部布局提供 CSS。手机卡片单列，编辑操作单列，顶部工具可使用紧凑双列。工作台保留内部编辑区域；窗口过短或控件换行时允许外框滚动，避免内容无法到达。

## 7. 无障碍与反馈

代码已提供共享 `:focus-visible` 描边、原生按钮禁用样式、长文本换行和减少动态效果支持。多个页面已接入可见标签、`role="status"` 与 `aria-live="polite"`。

后续新增或修改页面应遵守：

- 操作使用真实按钮，并明确 `type`；非提交操作为 `type="button"`。
- 完整标签页使用 `tablist/tab/tabpanel`、`aria-selected`、`aria-controls`，支持方向键与 Home / End；互斥分类按钮可使用 `aria-pressed`。
- 输入框有可见标签，图标按钮有可理解的名称。提交错误应保留输入内容。
- 执行中明确说明状态，按业务使用 `disabled`、`aria-busy` 和取消操作；不得只用颜色或动画表示进度。
- 切换、生成和重新绘制后，焦点留在合理位置；不能因输入触发绘制而丢失焦点。

这些行为需要逐应用验证。统一 CSS 的存在不等于所有页面已完成读屏和键盘验收。

## 9. 样式维护入口

`base.css` 负责主窗口结构；`ui.css` 保留旧应用嵌入适配；`settings/appearance.css` 负责表面、品牌和楼层框架；`metro.css` 与 `desktop-effects.css` 负责桌面；`ui/standard.css` 负责共享控件、语义布局和响应式；状态 iframe 另外加载 `ui-status.css`、`settings/appearance-frame.css` 与 `apps/status/workbench-frame.css`。

未来修改先回到对应样式归属，不继续叠加重复固定配色与高优先级覆盖。共享约定同步维护到仓库内 `ui/README.md`。
