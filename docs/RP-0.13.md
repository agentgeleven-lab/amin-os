# 0.13 跑团工作流

0.13 把人物、世界状态、物品与资源、人物关系、能力检定、持续效果、地图旅行与跨应用存档接成一套由玩家确认的跑团流程。骰点仍由 Amin OS 在插件内生成固定结果；需要写进本轮行动时，再把结果追加到酒馆输入框，由你使用酒馆原来的发送按钮发送。

本文说明各应用之间实际共享什么、一次变更如何确认，以及当前版本没有自动处理的规则。界面中的“当前楼层”或“当前分支”指当前聊天末尾及当前回复候选路径，不表示可以改写旧消息正文。

## 推荐开始顺序

1. 在「世界状态」建立人物需要使用的数字或进度字段，例如 `艾琳.力量`、`艾琳.生命`、`艾琳.理智`。
2. 在「人物卡」建立 PC / NPC，并把属性或技能绑定到现有世界状态字段。
3. 在「背包与账本」登记物品、装备、货币或其他资源；在「人物关系」建立有方向的关系。
4. 在「地图」确认当前位置和相邻路线，在「场景与时间」设置游戏时钟与当前场景。
5. 在「能力面板」发动能力；需要时先用人物绑定数值完成本地 D20 或 CoC 7 检定。
6. 到达重要节点时，在「跨应用存档」创建命名存档并导出 JSON 备份。

人物数值以世界状态为唯一数值来源。人物卡只保存人物资料和字段绑定；修改绑定数值会先显示预览，确认后直接更新对应世界状态字段。

## 共同的确认与保存方式

会改变剧情状态的操作使用同一套步骤：

1. 填写本次操作；需要原因的应用必须先填写原因。
2. 点击“预览”，核对对象、前后数值、游戏时间、场景或其他影响。
3. 点击“确认”一次。确认时会检查聊天、回复候选、当前数据与预览时是否一致；已经过期的预览会被拒绝。
4. 插件先把确认结果应用到当前内存，再保存聊天元数据。
5. 如果保存失败，页面保留已经确认的结果并暂停新的写入。点击“重试保存”只会保存同一个结果，不会再次扣除资源、重复移动、重掷骰子或重复发动效果。

同一聊天元数据一次只允许一项共享写入。切换聊天、切换回复候选或其他应用先改动了预览依赖的数据后，需要重新预览。

## 数据范围速查

| 内容 | 范围 | 分支行为 |
| --- | --- | --- |
| 人物卡与字段绑定 | 当前聊天 | 按当前消息正文与回复候选路径读取；不同候选隔离 |
| 物品、资源与变更账本 | 当前聊天 | 当前分支状态由历史记录重放得到 |
| 人物关系 | 当前聊天 | 当前分支只读取该路径上已确认的有向关系 |
| 场景、游戏时钟与持续效果 | 当前聊天 | 当前分支有独立的事件历史 |
| 地图与当前位置 | 当前聊天元数据 | 旅行把当前位置、场景和时间作为一次联合变更保存 |
| 骰点记录 | 当前聊天 | 结果一经掷出即固定；追加到草稿与发送是另外两步 |
| 命名存档与自动安全备份 | 当前聊天 | 恢复时把选定状态追加到当前聊天末尾 |
| 能力原文与能力库布局 | 当前酒馆用户 | 跨聊天共享；已经发动的效果仍按当时的规则快照保存 |
| 普通正文读取人物关系 | 当前聊天的显式设置 | 默认关闭，只读取当前分支中人物引用完整的已确认关系 |

页面顶部会说明“当前聊天”“当前分支”或“跨聊天共享”。切换聊天后，旧草稿不会被静默写进新聊天；部分页面会保留文本供复制，但保存会要求重新选择当前数据并预览。

## 人物卡与世界状态

### 建立人物

在「人物卡」选择“新增人物卡”，填写人物名称、PC / NPC 类型和备注。随后为人物添加属性或技能：

- 从现有世界状态中选择 `项目名.字段名`。
- 选择数字值，或进度字段的当前值 / 最大值。
- 选择不检定、D20 或 CoC 7。
- 为玩家看到的属性填写名称。

绑定缺失或字段类型不兼容时，人物卡会明确报错，不会根据同名字段猜测。进度字段要求最大值大于 0，且当前值在 0 到最大值之间。

### 修改数值

人物卡显示当前世界状态中的实时值。点击修改后先预览，再确认写入同一个世界状态字段；所有绑定此字段的页面随后读取同一结果。人物卡不会复制出第二套生命、理智或属性数值。

删除人物卡只删除人物登记。世界状态字段、物品、资源、账本和关系引用会保留，相关页面会把缺失人物显示出来，供你转交或修复。

### 人物卡内检定

为绑定属性选择检定：

- **D20**：绑定值直接作为修正值，可设置 DC 与优势 / 劣势。
- **CoC 7**：读取绑定技能值，可选择普通、困难或极难，并设置奖励骰 / 惩罚骰。

填写不超过 80 字的骰点名称，预览当前绑定值，再执行本地检定。结果固定后，点击“追加固定结果到草稿”。插件不会自动发送，也不会根据成功或失败自动扣生命、扣资源或施加效果。

## 背包与账本

「背包与账本」分为“物品”“资源与货币”“变更账本”。所有变更都要求原因，并在确认前显示涉及双方的前后值。

### 物品

- 登记或修正名称、所属人物、数量、装备状态与备注。
- 装备 / 卸下只改变明确的装备标记；数量为 0 的物品不能保持装备。
- 消耗不能让数量变成负数。
- 转交同时扣除原人物数量并增加接收人物数量；接收的物品默认未装备。
- 已有物品不能通过普通编辑直接换主人，需要使用“转交物品”留下双方账目。
- 只有数量为 0 的空物品记录可以显式移除，历史账本保留。

### 资源与货币

- 资源由名称、所属人物、余额、单位和备注组成，最多保留 6 位小数。
- 收入、支出和转交都写入账本；支出不能造成负余额。
- 转交按相同资源名称与单位处理，目标已有唯一匹配账户时合并。
- 单位由用户填写，插件不做币种或单位换算。
- 只有余额为 0 的账户可以移除，历史账本保留。

删除人物卡不会删除其资产。缺失人物名会显示为未解析引用，仍可把资产转交给当前分支存在的人物。装备不会自动改变能力检定或持续效果。

## 人物关系

关系从“发起者”指向“对象”。例如“艾琳信任贝克”和“贝克信任艾琳”是两条独立记录，需要分别建立。

- 关系类型必填；图上标签、强度和备注可选。
- 强度留空就保持未定义；显式填写 `0` 会保留为 0。插件不预设好感度刻度。
- 同一发起者、对象、类型与标签的重复关系会被拒绝。
- 有向关系图最多同时展示 32 个人物；完整可访问列表仍保留所有符合筛选的关系。
- 图中节点支持点击及键盘 Enter / Space 聚焦；可按方向和文字筛选。

人物改名时关系显示实时名称。人物被删除后，关系保留原稳定 ID 并显示未解析状态，不会自动绑定到另一个同名人物。

普通正文读取人物关系默认关闭。明确开启后，只附加当前分支、已经确认且人物引用完整的关系；草稿、其他回复候选和被替换的最新回复不会作为当前事实。人物关系不会由模型自动推断。

## 能力检定与固定骰点

在「能力面板」选择能力和发动方式后，可以展开“先做人物属性检定（可选）”：

1. 选择人物及其绑定属性。
2. 选择 D20 或 CoC 7，填写难度与本次修正。
3. 预览人物、能力、绑定字段、当前值和检定设置。
4. 确认本地掷骰。这个结果固定，不因重新生成回复而改变。
5. 需要写进本轮行动时，单独点击“追加固定结果到草稿”。
6. 需要发动持续效果时，再单独点击“确认检定后的效果”。

D20 可以把绑定值直接作为修正值，也可以显式选择按 D&D 属性值换算为 `floor((值 - 10) / 2)`；还可以添加额外修正、DC、优势 / 劣势与自然骰规则。CoC 7 使用绑定值加技能修正，并支持普通 / 困难 / 极难和奖励骰 / 惩罚骰。

聊天、回复候选、人物、绑定值、能力或限时时钟变化后，旧预览会失效。保存失败时固定骰值和已确认效果会保留；重试保存不会重掷或重复发动。同一骰点只允许由这条能力检定建立一次对应效果。

酒馆官方 `/roll` 不参与上述流程。Amin OS 只把已经固定的结果文字追加到输入框，不触发发送按钮；你可以先补充行动正文，再一起发送。

## 限时效果与游戏时钟

能力发动时可选择无限期，或按分钟、小时、天设置时长。限时计算只使用「场景与时间」中已经确认的游戏时钟：

- 新建限时效果从当前游戏时间开始。
- 编辑时保留时长不会重置计时；明确改成新时长会从当前时钟重新开始；取消时限会变为无限期。
- 暂停会冻结已用时间与剩余时间，恢复后继续下一段计时。
- 缺少时钟或时钟倒退到无法判断的时间时，插件不会猜测经过了多久。
- 到期记录仍然保留并标记“已到期”，但不再加入后续剧情提醒；插件不会自动删除或自动执行解除剧情。
- 明确把游戏时钟调回原有效期内时，效果可能重新处于有效状态。

推进时间或旅行的预览会列出本次新到期的效果。确认后再以新时钟计算当前提醒。

## 相邻路线旅行

旅行位于「场景与时间 → 旅行」。开始前需要在地图保存当前位置，并在场景应用设置游戏时钟。

1. 页面只列出从当前位置沿一条已发现道路可达的相邻地点。
2. 单向道路按方向限制；隐藏路线不显示，标记为不可通行或阻塞的地点 / 道路会被拒绝。
3. 选择目的地和通行方式。地图同时给出距离与速度时，耗时向上取整为整数分钟。
4. 可以明确覆盖地图估算；距离或速度不足时，必须手动填写 0 到 5,256,000 的整数分钟。
5. 预览会同时显示起点、目的地、路线、方式、时间前后、抵达场景及新到期效果。
6. 确认一次后，当前位置、游戏时钟、当前场景和本次到期预览作为一个联合变更保存。

目的地只有一个已关联场景时直接进入；没有关联场景时建立以目的地命名的空场景；有多个关联场景时必须明确选择。旅行不会跨多条道路自动寻路，也不是旧地图历史的任意还原工具。

保存失败后，重试只保存同一次抵达结果，不会再次移动、再次推进时间或再次切换场景。

## 跨应用存档

「跨应用存档」保存当前聊天中允许范围内的剧情状态。一个聊天最多保存 20 个命名存档；每次恢复前自动建立一份“恢复前”安全备份，保留最近 5 份。

### 会保存的内容

- 人物卡与绑定
- 物品、资源与账本
- 人物关系
- 场景与游戏时钟
- 持续效果
- 剧情档案
- 固定骰点记录
- 地图与当前位置
- 世界状态
- 势力资料
- 信息面板与信息资料库

### 不会保存的内容

- 酒馆聊天消息、回复候选或正文
- 全局扩展设置与界面布局
- 跨聊天共享的能力库等全局预设
- 模型 API 配置、地址、密钥或其他无关聊天元数据

### 创建、恢复与传输

1. 填写存档名称与备注，先预览模块摘要，再确认创建。
2. 恢复前查看各模块的当前状态与目标状态，以及来源聊天警告。
3. 确认恢复时，插件先在同一次操作中建立“恢复前”安全备份，再把目标应用状态追加到当前聊天末尾。
4. 恢复不会删除或倒退聊天消息。需要恢复对话正文、旧回复候选或酒馆分支时，请使用酒馆自己的分支或检查点功能。
5. 导出会生成 `amin-os-save` JSON。导入先检查格式、版本、大小和模块内容；确认导入只把存档收纳到当前聊天，仍需另行预览恢复。

单份存档上限为 8 MiB，当前聊天的存档仓库上限为 24 MiB。跨聊天恢复只应用插件剧情状态，不导入源聊天消息。剧情档案来源不属于当前聊天时，会保留正文、清除旧来源并关闭对应引用；已追加骰点会恢复为尚未追加状态，因为插件不会改写当前酒馆输入框。

## 一次完整的行动示例

假设玩家让艾琳从北门赶往钟楼并使用“疾行”：

1. 人物卡从 `艾琳.敏捷` 读取当前值。
2. 在能力面板预览并完成本地 D20 检定；把固定结果追加到草稿，但先不发送。
3. 单独确认“疾行”效果，并设置 30 分钟时长。
4. 到「场景与时间 → 旅行」选择北门相邻的钟楼，核对估算耗时、抵达场景和到期效果。
5. 确认旅行一次。地图位置、游戏时钟和当前场景一起更新；若 30 分钟已过，“疾行”显示到期并停止加入提醒。
6. 回到输入框补充行动文字，检查固定骰点块，再使用酒馆发送按钮发送同一条消息。
7. 在关键节点创建跨应用存档，留作之后恢复剧情状态。

这套流程不会自动决定移动是否成功、扣除补给、结算伤害或修改人物数值。需要变化时，在对应应用中再次预览并确认。

## 当前限制与验证边界

- 人物卡是状态绑定和检定入口，不是完整 D&D / CoC 角色构筑或战斗系统。
- 背包不计算负重、装备槽、装备加成、货币汇率或消耗品效果。
- 关系不自动推断、不自动变更，也没有预设的好感度刻度。
- 限时效果以手动确认的游戏时钟为准，不使用现实时间，也不会自动生成结算剧情。
- 旅行只处理当前地图的一跳相邻路线，不负责多段路线规划或随机遭遇。
- 跨应用存档恢复的是当前聊天末尾的插件状态，不是酒馆聊天回滚。
- 最终源码检查覆盖 285 个 JavaScript 模块，自动测试 832 / 832 通过；Headless Edge 的隔离模拟酒馆完成 9 组功能流程和 23 份 1280 / 320 / 390 / 430px 布局检查，运行时错误为 0。它使用模拟 SillyTavern 和桌面浏览器手机视口，不能替代真实 SillyTavern / TauriTavern、模型供应方、物理手机触控与软键盘验收。
