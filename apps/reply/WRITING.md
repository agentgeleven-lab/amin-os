# 回复选项：生成候选与改写草稿

本次合并尚未发布；旧版本文风转换入口保留为兼容入口。

## 两个工作页

- **生成候选**：保留角色扮演／作者模式、回复主体、人称、方向、数量和草稿扩写。点击候选正文填入输入框；也可以复制或“继续改写”。
- **改写草稿**：手动填写原文、读取聊天输入框，或接收候选。转换结果可编辑、复制、填回及撤销填回。
- “继续改写”只转交文字，不调用第二次 AI，也不发送消息。改写页已有不同原文时拒绝覆盖，请先复制保留或清空。
- 切换工作页不销毁原文、结果或尚未保存的预设编辑；原文与结果仍按聊天隔离，属于页面内临时草稿，刷新前请自行复制保留。

## 楼层内窗口

点击消息楼层的「✧ 回复选项」，窗口内也有「生成候选／改写草稿」两页。候选的“继续改写”和“管理文风预设”都在当前楼层窗口内完成，不跳转 OS 主窗口。

- 候选生成以及参考聊天文风只使用到当前楼层为止的聊天；不会读取后续楼层正文。参考文风在此范围内取最近 16 条完整非系统正文。
- 主窗口和多个楼层可以同时打开，各窗口的原文、结果、未保存编辑和任务分开保留。修改其他窗口的模式或选择，不会偷偷替换当前窗口显示的选择；新窗口沿用最近保存的默认设置。
- 风格条目库仍共享。另一窗口修改正在使用的条目时，对应等待结果会失效；修改无关条目或关闭其他窗口，不会取消当前任务。
- “填回”仍只写入当前聊天输入框，有新草稿时阻止覆盖，不自动发送。
- 保留楼层窗口顺序、尺寸、收起方式及托管挂载。收起／关闭会释放该窗口的临时草稿与结果，请先复制需要保留的内容；仅切换工作页不会丢失草稿。
- 楼层被替换、删除、切聊或聊天 metadata 替换时，会取消并清理旧窗口，迟到结果不会落入新窗口。

## 内容风格库

两页都有单选“内容风格”和“管理内容风格”。每个条目包含名称、提示词，支持新增、编辑、复制、两次点击确认删除，以及恢复已删除风格（撤销）。提示词不按字符数截断；空提示词表示不追加要求。

- 首次使用从旧回复设置迁移正常、NSFW、暴力、无厘头四个条目，原自定义提示词原样保留，旧设置也不删除。
- 两页共用条目库，但独立保存选择；改写页默认“不附加内容风格”。
- “不附加内容风格”是不可删除的空选项；所选条目消失时安全回退，不偷偷换成另一种风格。
- 只有当前选中的提示词参加请求，其他条目不会一起注入。
- 编辑所选条目后需保存或放弃修改才能使用它。另一页编辑或删除风格也会取消当前等待，避免迟到结果覆盖。
- 条目保存到酒馆 `extensionSettings.amin_os_content_styles_v1`。不要填写 API 密钥；名称／提示词包含疑似密钥时拒绝保存。

## 文风与内容风格不同

内容风格决定内容取向；文风决定用词、句式、节奏和表达方式。例如可以使用“悬疑内容风格＋简洁文风”。

文风选项：不额外指定、参考当前聊天、自定义文风。生成页可直接应用文风，一次请求生成候选，不强制先生成再改写；“管理文风预设”打开改写页的预设编辑器。两页共享原 `amin_os_stylewriter_v1` 中的文风条目，但生成页单独保存所选文风。

参考文风使用最近 16 条已加载的非系统正文，每条完整传递；它不是无限聊天记录。参考样本只用于学习表达，不应把样本人物、事件套入原文。自定义及不额外指定模式不为改写任务额外读取聊天、角色卡、世界书或能力效果。

改写始终要求保持事实、指代、视角、人物关系与事件顺序；内容风格不能授权自动扩写。AI 的遵循效果仍须人工检查。

## 兼容与安全

- 旧 `stylewriter` 磁贴、应用 ID 仍可打开改写页；新默认布局只提供一个回复选项入口。旧自定义磁贴布局不被清除。
- 候选继续使用 `reply` API 渠道，改写继续使用 `stylewriter`（AI 设置中仍称“文风转换”）渠道；不会把两份不同配置合并覆盖。
- 共享异步提示词预设仍沿用全局选择，本次没有新增按应用独立异步预设。
- 改写页继续读取原文风转换的独立外观设置；无独立配置时跟随全局。
- 保留取消、切聊／metadata 替换保护、输入框草稿检查、迟到结果拒绝和只填入不发送。楼层候选在当前楼层窗口内转交改写，仍先检查聊天身份与楼层有效性。
- 自定义 requestBody 若覆盖 `messages`，仍会覆盖上述组装提示；请在 AI 任务预览中检查最终请求。

## 开发验证

- `npm test`：模型、存储、迁移、DOM 双替身与模拟请求回归。
- `npm run check`：JS 语法、相对导入、JSON 与入口检查。
- `node apps/stylewriter/scripts/browser-smoke.mjs`：隔离 Chromium 真 DOM，虚构聊天和模拟 AI，含主窗口／多楼层共存、就地转交、输入保护、监听清理、托管挂载模拟与 390px 布局。必要时设置 `AMIN_BROWSER` 和 `AMIN_REPO`。

这些检查不是实际 TauriTavern／安卓设备或真实模型验收；本轮仅推送源码，不更新本机安装目录、不创建 Release 或升级版本。

## 0.16.4：关联资料与候选调整

- 展开“本次参考资料”，可以按来源启停并取消单条引用；刷新或生成时读取当前变量，不添加后台模型请求或轮询。来源开关为应用设置，单条排除仅保留在当前窗口，切聊清除。
- 关联资料从已迁移且完成回放的小白变量 2.0 读取，按主体和当前场景筛选并限制总量；不会写入变量。旧楼层窗口不把当前较新变量当成历史资料。资料没有可靠的角色可见性标记时会保守筛选，仍需检查人物实际已知信息。
- 每条候选可以“换一个同方向方案”，或展开“调整这一条”输入修改要求、使用快捷语气调整。必须保留的片段须来自原候选；模型未逐字保留时拒绝替换原结果。
- 勾选“保留这条”后使用“保留满意项，重抽其余”，只更新未保留的位置。普通“生成 / 换一批”仍生成全新一批。
- 修改失败、取消或超时均保留原候选；聊天、设置或资料已变化时不接纳迟到结果。修改候选不会自动修改已经填入的聊天草稿。
- 生成要求、作者要求和两个模式提示词支持至 32000 字，超限明确报错。任务规定输出格式与主体，用户要求优先于方向、文风及默认篇幅。模型仍可能漏掉语义要求，只有格式、原句保留等可确定条件做自动校验。
- 独立 API 配置中的自定义 `messages` 会替换整份任务，因此回复选项会阻止此请求并提示移除覆盖。酒馆 Quiet 路由的完整预设由宿主组装，仍须在酒馆提示词查看器检查；Amin 的参考开关仅控制自身追加的关联资料。
