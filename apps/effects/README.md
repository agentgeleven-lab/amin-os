# 持续效果 · 第一版

在 Amin os 开始屏打开「持续效果」。界面遵循 ui/README.md，自动继承全局主题、字号、圆角和间距，也可在 OS 设置中单独配置。

1. 技能库 → 刷新世界书列表 → 选择世界书 → 读取所选世界书。列表包含全局启用、角色绑定、附加、聊天、人格和内嵌世界书，并标注来源；选定一本后才读取其有效非空条目。
2. 选择技能条目，查看原文，填写或精简持续提醒规则并保存关联。原世界书不会被写入。可在技能库编辑提醒，编辑只影响之后建立的效果。
3. 生效中 → 建立生效记录，填写持有者、目标、作用层面、当前指令与解除条件。技能原文和提醒规则随效果保存快照。
4. 「调整 / 转让」可修改持有者、指令与条件；「解除」需要填写依据。「分割」结束原记录，一次建立多个子记录，继承原规则、指令与条件。
5. 提示预览可查看下次生成的实际提醒内容、开关和字符上限。超过上限会明确提示而不截断。默认 30000 字符，不等于模型 token 上限。

普通聊天生成使用 GENERATION_AFTER_COMMANDS 和 setExtensionPrompt（聊天深度 0，不参与世界书扫描）。Amin os 共用 AI 请求也加入相同效果资料，独立 API 与宿主 API 都走这一层。提示会在生成结束、取消、聊天切换和楼层变化时清理。接口不支持时，界面明确提示。

技能关联与变更记录保存在当前聊天 metadata 的 amin_os_effects_v1，不保存进角色的原世界书。变更以当时聊天前缀的精确内容与回复分支作为证据；删除、修改、切换分支使证据不匹配时，该条及后续变更不再生效。恢复相同分支可重新匹配记录。重新生成/切换回复时不注入将被替换的最后一条角色消息上建立的效果。

第一版不自动判断发动、死亡、继承、技能胜负、重叠层面的优先级或解除条件。用户需手动确认并操作。分割采用明确列出的范围，不会自动推导“身体减去右手”这样的集合；相同目标与完全相同层面禁止重复建立，语义重叠需用户检查。旧分支记录保留以供查看。精确前缀与原文快照会增加聊天文件体积。

代码检查和模拟宿主测试不能替代实际酒馆验证；模型是否遵守规则仍取决于上下文预算和模型能力。


## AI 编写提醒

关联技能或编辑提醒时，可填写补充要求并点击「AI 编写提醒」。使用共享 AI API 和预设，发送所选技能完整原文、现有规则和补充要求，不附加当前生效实例。AI 草稿单独显示，支持编辑、采用到规则框及取消；采用后仍需保存关联。离开编辑页或聊天变化后不会应用迟到结果。原世界书与已发动效果的规则快照保持不变。实际提示与任务可在 AI 设置中查看。
