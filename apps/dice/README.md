# 骰子

Amin OS 内的独立本地骰子应用，适合把桌面角色扮演检定和行动正文一起发送。

## 使用

1. 在「通用骰」「D&D」「CoC 7」中填写规则，点击「掷骰并记录」。
2. 查看真实候选、舍弃骰、修正值及结果；需要重掷时明确点击「用相同设置重掷」。
3. 单条追加，或勾选多条后追加到聊天草稿。原有行动正文保持原样。
4. 继续编辑正文，再使用酒馆自己的发送按钮。所有选中骰点和正文在同一条用户消息中发送。

应用不调用酒馆 roll 宏、不自动发送消息、不在生成、重试、续写或切换回复时掷骰。每次掷骰保存独立 ID、时间、规则快照、全部候选和固定输出文字。消息重试沿用已发文字。关闭骰子页后，共享服务继续监听发送事件。

「撤销刚才的追加」仅在聊天和草稿仍完全匹配时恢复原稿；手动编辑后请自行删除骰点段落。回复/改写模块可使用 draft.js 的精确匹配接口保留已登记骰点。

## 规则范围

- **通用公式**：NdS，多项整数加减，以及 khK / klK 保留最高 / 最低 K 枚。例如 2d6+3、1d8+1d4-2、4d6kh3。不支持乘除、括号、脚本或爆炸骰。D4、D6、D8、D10、D12、D20、D100 快捷按钮立即掷骰。
- **D&D D20**：普通、优势取高、劣势取低，单独输入总修正与可选 DC / AC。「属性检定 / 普通豁免」只比较总值；「攻击」采用自然 1 自动未命中、自然 20 自动命中并标记重击；另提供明确标注的自然 1 / 20 自动失败 / 成功房规。优劣势同时存在应选普通。不自动计算伤害翻倍、角色熟练、抗性、特殊重掷、死亡豁免或战斗回合。
- **CoC 第七版**：技能/属性 1–999；普通、困难一半和极难五分之一向下取整。奖励、惩罚各支持 0–2 枚，数量相互抵消后增加十位骰，所有候选共享个位。先把 00 + 0 读作 100，再取最好/最差候选；因此 00/30 + 0 奖励取 30，惩罚取 100。
- **CoC 成功结果**：01 大成功；成功等级依据技能本值、一半和五分之一，同时独立显示是否达到所选难度。本次所需目标低于 50 时 96–100 大失败，否则仅 100；例如技能 55 的困难检定目标为 27，96 即大失败。主持人的孤注一掷、对抗胜负、幸运消耗、理智损失和特殊规则应另行裁定。
- **批量**：同一设置重复 1–20 次，每次保留独立明细，整批作为一条记录。

这是一套检定辅助工具，不是完整 D&D 或 CoC 规则引擎。重掷按钮只产生新记录，不自动宣告 CoC「孤注一掷」合法，不抹去先前失败。

规则参考：

- [D&D Free Basic Rules 2024 · Playing the Game](https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game)：D20、优劣势、攻击自然 1 / 20。
- [Chaosium 官方 CoC Wiki · Game System](https://cthulhuwiki.chaosium.com/rules/game-system.html)：百分骰、难度、奖惩骰。
- CoC Keeper Rulebook 第七版第 89–91 页：大成功 / 大失败，本次难度目标影响大失败阈值。官方简化 wiki 未收录完整大失败说明。

## 保存及失败

预设保存在 extensionSettings.amin_os_dice_presets_v1，可跨聊天使用，载入本身不会掷骰。历史保存在各聊天的 chatMetadata.amin_os_dice_v1，应用不自动修剪历史；页面每页展示 30 条。

随机数来自 crypto.getRandomValues，采用拒绝采样消除取模偏差。公式、骰数、骰面、批量和字符串都有边界，解析不使用 eval。单公式最多 100 枚骰，批量总计最多 400 枚。

骰点保存失败时保留已固定的内存记录并显示「重试保存固定骰点」，重试不会消耗随机数。未保存骰点在关闭/刷新页面前需要成功保存；宿主若使用延迟保存接口，只能确认宿主接受了保存请求，不能保证磁盘已落盘。

发送绑定仅在 MESSAGE_SENT 事件能对应到新出现的用户消息，且消息包含完整固定骰点文本时进行。仅在骰子 metadata 保存楼层索引和消息快照，不修改历史消息。文本编辑、删除或分支回退导致不匹配时显示「原消息已变化 · 保留原骰点」，作为历史凭据保留。追加起点与聊天身份一起保存，重载后可恢复同一聊天的待发送匹配；切换到其他聊天或新分支不会沿用旧聊天的待发送标记。

## 集成

~~~js
import { mount } from './apps/dice/view.js';
import { getSharedDiceService } from './apps/dice/service.js';

const service = getSharedDiceService();
const view = mount(target, { api: service });
// view.open(), view.refresh(), view.dispose()
~~~

加载 apps/dice/style.css 与共享 ui/standard.css。页面销毁仅解除视图订阅，不销毁共享发送监听器；完整插件卸载时可显式 service.dispose()。

固定草稿接口：

~~~js
import { splitDiceDraft, mergeDiceDraft } from './apps/dice/draft.js';
const snapshot = splitDiceDraft(originalDraft, currentContext);
// 仅 snapshot.body 参与正文改写；保留调用方已有的聊天和草稿变化校验。
const merged = mergeDiceDraft(replacement, snapshot);
~~~

拆分只识别当前聊天历史中完整精确匹配的已登记文字，不能把任意相似标题当作骰点。渲染内容使用 textContent。

测试命令：node --test test/dice*.test.js。纯逻辑与模拟宿主测试涵盖分布边界、公式限制、CoC 00、目标难度、大失败、D&D 自然骰语义、批量快照、草稿保护、保存失败不重掷、跨聊天隔离及消息绑定。真实酒馆版本的发送事件时序、保存持久化及手机触摸体验仍需实机验证。
