# 剧情档案

伏笔与编年史共用一个聊天内应用。入口：`view.js` 的 `mount(target, options)`；服务入口：`service.js` 的 `getSharedService()`；共享 AI 可读取 `model.js` 的 `currentPrompt(ctx)`。所有布局直接使用 Amin UI 的 `amin-*` 语义类，不维护独立主题或宽度。

## 用户操作

- **伏笔**：标题、内容、关联人物、待回收／已回收／已放弃、来源楼层、可选剧情时间。可设置经过多少个后续楼层后在列表显示提醒；提醒不会自行给模型发送内容或推进剧情。
- **编年史**：手工整理或选择已加载的真实楼层范围，让 AI 起草。AI 的结果先出现在可编辑预览中，点击“采用草稿到正文”后仍须明确保存。
- **引用**：每条默认关闭。只有已保存、用户明确启用、属于当前分支且来源仍有效的档案参与提示。引用预览显示最终档案文本；超出字符上限会完整拒绝附加，不会截断事实。
- **导入／导出**：导出当前分支档案及原始来源正文。导入先验证和预览，再明确保存；生成新 ID，引用关闭，来源仅保留说明，须重新绑定本聊天实际楼层才能启用引用。

## 归属与来源

数据保存在当前聊天的 `chatMetadata.amin_os_journal_v1`。不会共享到其他聊天，不修改世界书、信息面板改写历史或场景状态。剧情时间读取场景应用的已确认时钟并作为快照保存；现实保存时间单独记录。

所有建立、编辑、引用切换和删除均保存操作 ID、现实时间及操作发生时的完整消息前缀。消息证据包含发言者、用户标记、正文和回复候选编号。查询较早楼层或不同分支时，只回放精确匹配的事件，未来修改不会出现在过去。删除也是一个事件，不破坏较早分支的记录。

来源范围采用从 1 开始的界面楼层号，内部为从 0 开始、包含首尾的范围。保存每条原文和版本证据。改楼、删楼、切换候选或分支不匹配后，条目不再参与当前引用；可在“来源变化 / 其他分支”中查看保存时的正文，再主动复制为本分支新条目。导入及未绑定来源的手工条目也不能引用。

消息前缀用于保守判断，不能识别所有外部修改的历史语义。例如，更早的一条无关消息被修改，也会使之后建立的档案暂时离开当前分支；用户需核对并重新绑定。界面只处理宿主当前加载的 `ctx.chat`，不会自行加载未在当前上下文内的历史消息。

## AI 与保存

请求前冻结选定原文、现有正文、补充要求、渠道和共享预设；使用 `getAI().capture('journal')` 与 `generate('剧情档案 · 编年史', ...)`。编年史请求关闭持续效果、剧情档案和场景的附加引用，以维持用户指定的来源范围；用户自行配置的共享／酒馆预设仍按所选渠道生效。

生成期间切换聊天、来源改变、编辑框继续改动或其他窗口保存档案，旧结果均不采用。表单令牌同时检查聊天身份、元数据对象、消息前缀与档案基线。保存成功的令牌不会重复执行；失败时仅回滚本应用数据，保留编辑内容供重试。服务销毁与宿主消息事件会取消尚未完成的草稿。

模块支持宿主 `GENERATION_AFTER_COMMANDS` 的普通、重生成、切换候选和续写流程，生成结束／停止／聊天切换时清理临时提示。重生成与切换候选时排除将被替换的最后一条角色消息。缺少提示接口时，管理与复制预览仍可使用。

## 验证范围

`node --test test/journal-core.test.js test/journal-view.test.js` 覆盖模型、宿主服务及 DOM 双替身交互。包括来源范围、过期与跨聊天结果、草稿确认、独立引用、导入预览、保存失败恢复和分支回放。

这些是离线测试。真实酒馆内的宿主事件时序、API 供应方返回、手机输入法与实际楼层窗口布局仍需要整体验收；测试通过不等于供应方请求或实际移动设备已验证。
